# Sahadhyayi Performance Optimization Roadmap

## Goals

Improve first-load speed, responsiveness, and media loading while preserving every existing feature and route. Prefer measured, incremental improvements over a framework rewrite or raising budgets to hide regressions.

## Current measured baseline

The production build on the image-and-shell optimization branch reported:

| Metric | Current measurement | Guard |
| --- | ---: | ---: |
| Main application JavaScript (Brotli) | 120.01 KB | 175 KB |
| Static initial-route JavaScript (Brotli) | 253.53 KB | 280 KB |
| All built client JavaScript (Brotli, summed per asset) | 686.11 KB | 690 KB |

The all-assets measurement sums each built JavaScript asset separately. A visitor does not download every route chunk on the first page view, so the initial-route budget is checked independently. The 650 KB all-assets target remains the next milestone, not a result already achieved.

## Image payload improvements

The build pipeline creates optimized WebP variants from the original source images. The latest CI build reported:

| Source | Original | Generated | Reduction |
| --- | ---: | ---: | ---: |
| Site logo | 1,173 KB | 3 KB | 99.7% |
| Brand artwork used on the About page | 1,347 KB | 8 KB | 99.4% |
| Library hero background | 217 KB | 94 KB | 56.8% |
| **Combined** | **2,737 KB** | **105 KB** | **96.1%** |

Book Expert artwork is generated by the existing image optimizer; its latest build log reported 1,730 KB reduced to about 40 KB. The static build check also enforces per-image ceilings so future source replacements cannot silently ship oversized artwork.

Open Graph/Twitter metadata keeps using the existing source image for compatibility; in-page images, favicons, and the Library hero use the optimized derivatives.

## Implemented

- Social feed, reader maps, friends management, and group panels load on demand.
- Global search, messages, and notifications load their code when opened.
- Desktop-only discovery sidebar queries are skipped on mobile while the sidebar is hidden.
- The global footer is loaded when the reader approaches it; the onboarding tour initializes after the app is idle.
- The Community Pulse dialog loads only after a user opens Live Website Stats.
- The asset preparation script runs before development and production builds; generated files are ignored by Git.
- CI checks targeted social/navigation tests, the production build, main and total JavaScript budgets, initial-route JavaScript, and generated-image budgets.

## Next milestones

1. **Reach 650 KB total client JavaScript.** Use a module-level bundle report and inspect the largest shared and route chunks. Prefer safe tree-shaking, removal of genuinely unused imports, and reuse of shared dependencies; do not remove product features.
2. **Reduce initial-route JavaScript below 240 KB.** Audit the application shell and static imports, especially work only needed by secondary routes. Verify the homepage and signed-in dashboard still render their key content immediately.
3. **Measure real page experience.** Run Lighthouse on the homepage, Library, book details, Social feed, and Reading Rooms at mobile and desktop viewports. Track LCP, INP, CLS, request count, and transferred bytes.
4. **Validate all major interactions.** Check authentication, book search/downloads, reading progress, social posts/quotes, likes/comments, maps, rooms, analytics, and Book Expert before merging performance changes.
5. **Keep regression guards strict.** Only lower or change budgets after CI measurements prove the target is met; never raise the target just to silence a failure.

## Acceptance criteria

- No route or feature is removed.
- Optimized assets exist in the built output and remain under their configured per-image budgets.
- Main bundle stays under 175 KB Brotli, initial-route JavaScript under 280 KB Brotli, and all client JavaScript under the 690 KB interim budget.
- Targeted tests, production build, size checks, and license compliance pass before merge.
- Production rollout is evaluated separately from pull-request CI.
